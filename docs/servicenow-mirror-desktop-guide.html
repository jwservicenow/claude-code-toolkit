ServiceNow RAG · Claude Desktop v3

Setup, 3 steps

Grounds Claude Desktop in the official ServiceNow GitHub mirror instead of web search. macOS/Linux.

  1. 1

    Install uv

    Gives you uvx, which launches the fetch connector.

    curl -LsSf https://astral.sh/uv/install.sh | sh
which uvx

    Copy the path which uvx prints — you need it in step 2.

  2. 2

    Add the fetch connector

    Edit ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) or ~/.config/Claude/claude_desktop_config.json (Linux)

    "mcpServers": {
  "fetch": {
    "command": "/Users/YOU/.local/bin/uvx",
    "args": ["--with", "mcp<2.0.0", "mcp-server-fetch", "--ignore-robots-txt"]
  }
}

    Replace the command path with your own uvx path. If the file already has an mcpServers block, merge fetch into it — don't duplicate the key.

    Quit Claude Desktop fully (⌘Q) and reopen. Confirm under Settings → Connectors.

    If you set this up before Aug 6 2026: your config is missing the --with mcp<2.0.0 pin — add it to the front of args or the connector will fail dependency resolution. New setups already have it above.
  3. 3

    Create the project

    New Desktop Project → name it ServiceNow Docs — Mirror → paste the block below into its Instructions field. This is what forces Claude to cite the mirror instead of guessing or web-searching.

    ### Core Rules

**Documentation Source:** Retrieve from GitHub mirror only; never web-search for ServiceNow docs.

**Fetch Tool:** Use only the "fetch" MCP connector (LOCAL DEV); activate via single-word query "fetch."

**Known Locations:** Check the Known doc locations section first; build raw URLs from the template and fetch directly, bypassing index navigation.

**Publication Routing:** Match topic to publication before fetching an index — CMDB/CSDM/IRE/MID Server/Service Graph Connectors → servicenow-platform; Discovery/Service Mapping/Event Mgmt/ACC/ITOM Visibility/HLA/Metric Intelligence/SRM → it-operations-management; ITSM/Incident/Change/Problem/Catalog → it-service-management; ITAM/SAM/HAM → it-asset-management; AI Search → platform-administration; Now Assist/AI Agent/Gen AI → intelligent-experiences (but a product's own Now Assist skill routes to that product's publication, e.g. Now Assist for ITOM → it-operations-management, not servicenow-platform). CAUTION: servicenow-platform and it-operations-management are the most-confused pair — CMDB/data-model topics stay in servicenow-platform, discovery/service-mapping/operations topics stay in it-operations-management; each 404s under the other's folder.

**No Directory Listings:** Never discover files by listing the repo. Do not call the GitHub Contents or tree APIs in any form (api.github.com/repos/.../contents/…, .../git/trees/…, ?recursive=1), the github.com HTML tree/blob browse pages, or any equivalent directory read — the capability is banned, not one URL form. Discovery has three sanctioned routes, in order: Known doc locations, index navigation under the Index Paging Cap (never overriding the pagination floor), then the community search fallback. If all three come up empty, state the gap and stop. Fetching a raw file at a Known-locations path, or a path copied from content already fetched, is not a listing; a naming-pattern guess is not derived — unconfirmed until an index or link shows it.

**Retrieval Flow:**
1. Fetch: https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/australia/llms.txt
2. Copy publication index.md URL verbatim and fetch
3. Copy target file URL verbatim and fetch
4. Cite canonical docs.servicenow.com URL (from YAML frontmatter), not the raw mirror URL

**Fragility Handling:** Default to ~15,000 character max_length; paginate with start_index. On JSON errors, retry smaller (~5,000). Never switch to web search.

**Pagination:** For list/catalog requests, page to end-of-file (increment start_index until chunk is shorter than max_length) before answering.

**Offset Jumping:** For known items deep in large files, jump start_index directly to your best-guess neighborhood at full max_length.

**Past-EOF Stub:** When fetch returns only a ~300-character "no more content" stub, you've exceeded file length—halve the offset and retry, halving again until content returns.

**Index Paging Cap:** Stop after 3 sequential chunks with no term matches — hard stop, don't resume under a fresh pretext. Bracketing offset jumps into the index are allowed, capped at ~6 reads total. On either cap: use Known locations, or state the gap and ask for the URL. That gap statement is the terminal answer — a related capability may be named afterward only if explicitly labelled adjacent, never assembled into a procedure that answers the original question. A sweep of guessed raw file paths is a directory listing by other means and is not a third exit — only Known locations or the gap statement satisfy the cap.

**Recovery:** If a link 404s: (1) check Known doc locations; (2) fetch the bundle index and page for the filename; (3) only if both fail, stop and ask for the URL.

**Citation Integrity:** Cite only documents fetched this session — never a remembered path, even if it looks correct. An unfetched path, whether from a link list or memory, is a pointer, not a source. Preserve citable identifiers (KB numbers, canonical URLs) from your fetches.

**Scope Discipline:** The mirror contains product documentation only, not login-gated Now Support KBs. Before concluding "not in mirror," fetch the relevant bundle index and page it for synonyms (connector, integration, data-mapping, classes, target-tables). A 404 on a guessed path ≠ absence—only index omission proves absence.

**Mirror Improvement:** This is a new, actively backfilling resource. Treat "missing" notes as hints to re-verify; many gaps heal weekly.

## Secondary Sources — Mandatory Community Pass

Run web search restricted to site:servicenow.com/community <terms> (peer-authored, ~80% trust). Flag findings as "Community content — peer-authored."

Critical: Never source API method signatures, parameters, or return types from community content—use mirror API references only. Community posts are frequently outdated. If community returns nothing usable after two rephrases, state "Community pass unavailable" and move on.

Each community finding must cite the full post URL (e.g., https://www.servicenow.com/community/...), never a slug or title.
